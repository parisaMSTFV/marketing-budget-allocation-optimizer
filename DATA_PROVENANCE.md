# Data Provenance

This repository uses a fully synthetic marketplace portfolio generated by
`src/marketing_allocation/simulation.py`.

The generator creates weekly aggregate observations for four generic product
categories and three generic marketing channels. Each observation contains
spend, a seasonal context index, and a noisy incremental-contribution estimate.
The response parameters, spend ranges, category names, channel names, dates,
budgets, constraints, and reported results are fictional.

The generator deliberately gives the fictional historical budget a stable
legacy allocation bias, so the historical policy is not assumed to begin at
the economic optimum. This assumption is explicit in the simulation code and
is one reason the optimizer can create value in the case study.

No customer records, transaction exports, campaign names, employer schemas,
internal thresholds, proprietary code, or confidential business results were
used. The row-level generated files are excluded from version control; a small
sample is committed only to make the schema easy to inspect.

The simulator's hidden response parameters are used only to evaluate policy
regret and create an oracle upper bound. A real planning team would not know
those parameters.
